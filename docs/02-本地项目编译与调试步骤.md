# 本地项目编译与调试步骤

> 适用：在本机（不通过 Docker）运行、编译检查、调试两个示例项目。
>
> 目标：任何一次改动后，都能用固定命令确认「语法通过 → 可导入 → 可运行 → 测试通过」。

---

## 1. 通用环境准备

### 1.1 安装 Python 3.12

```powershell
py -0p
py -3.12 --version
```

若没有 3.12，到 https://www.python.org/downloads/windows/ 安装，并勾选 `Add python.exe to PATH`。

### 1.2 VS Code 插件

| 插件 | 用途 |
|---|---|
| Python（Microsoft） | 解释器选择、运行、调试 |
| Pylance | 类型提示与跳转 |
| SQLite Viewer（可选） | 查看 `.db` 文件 |

### 1.3 虚拟环境与激活

Windows PowerShell 默认可能禁止执行脚本。若激活报错：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

每个项目单独建虚拟环境，互不污染：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
```

退出：

```powershell
deactivate
```

## 2. 采集项目 `examples/01-jd-taobao-spider`

### 2.1 初始化

```powershell
cd examples/01-jd-taobao-spider
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2.2 编译（语法）检查

不要直接 `compileall .`，否则会扫描 `.venv`。用明确的文件列表：

```powershell
python -m compileall -q adapters net utils config.py models.py storage.py pipeline.py export.py main.py conftest.py
```

无输出即通过；有语法错误会打印文件与行号。

### 2.3 导入检查

```powershell
python -c "import main, pipeline, storage; print('imports ok')"
```

### 2.4 运行

```powershell
# 零网络离线演示：京东 + 淘宝
python main.py

# 单站点离线
python main.py crawl --site jd --keyword 手机 --offline

# 查看统计
python main.py stats

# 导出
python main.py export --format csv --site jd
```

真实模式（务必先确认合规）：

```powershell
python main.py crawl --site jd --keyword 手机 --pages 1
```

### 2.5 测试

```powershell
pytest -q
pytest -q -vv          # 看每个用例名
pytest -q --lf         # 只跑上次失败的
```

### 2.6 VS Code 调试配置

在仓库根目录新建 `.vscode/launch.json`（或合并已有配置）：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "采集-离线演示",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/examples/01-jd-taobao-spider/main.py",
      "cwd": "${workspaceFolder}/examples/01-jd-taobao-spider",
      "console": "integratedTerminal",
      "justMyCode": false
    },
    {
      "name": "采集-京东真实",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/examples/01-jd-taobao-spider/main.py",
      "args": ["crawl", "--site", "jd", "--keyword", "手机", "--pages", "1"],
      "cwd": "${workspaceFolder}/examples/01-jd-taobao-spider",
      "console": "integratedTerminal",
      "justMyCode": false
    }
  ]
}
```

调试建议断点：

| 位置 | 观察什么 |
|---|---|
| `pipeline.py` 的 `crawl` | 站点、页码、是否 offline、是否被 robots 跳过 |
| `adapters/jd.py` / `taobao.py` 的 `parse` | 解析出的商品数量与字段 |
| `storage.py` 的 `save_many` | `inserted` 是否为 0（去重是否生效） |

### 2.7 临时调试技巧

```python
# 在任意函数内插入断点，运行到此处会进入 pdb
breakpoint()
```

pdb 常用命令：`n`（下一行）、`s`（进入函数）、`c`（继续）、`p 变量`（打印）、`l`（看上下文）、`q`（退出）。

日志：

```powershell
python -c "import logging; logging.basicConfig(level=logging.DEBUG); import main; main.main(['crawl','--site','jd','--offline'])"
```

### 2.8 采集项目常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: adapters` | 不在项目根目录运行 | `cd examples/01-jd-taobao-spider` |
| `FileNotFoundError: fixtures/...` | 路径被移动 | 确认 `fixtures/jd_search.html`、`taobao_search.html` 存在 |
| `inserted=0` | 重复数据被唯一键忽略 | 正常现象，说明去重生效 |
| 解析 0 条 | 选择器失效或页面改版 | 改对应 adapter 的选择器，用 fixtures 回归 |
| `httpx.ConnectError` | 网络/代理/站点限制 | 先用 `--offline` 验证逻辑，再排查网络 |
| 激活脚本被禁止 | PowerShell 执行策略 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

## 3. 电商平台 `examples/02-ecommerce-platform`

### 3.1 初始化

```powershell
cd examples/02-ecommerce-platform
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

可选：复制配置

```powershell
copy .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

把输出写入 `.env` 的 `SECRET_KEY`。

### 3.2 编译（语法）检查

```powershell
python -m compileall -q app tests
```

### 3.3 导入检查（能捕获大部分启动错误）

```powershell
python -c "from app.main import app; print(app.title)"
```

预期输出：`PyShop 电商平台`。

### 3.4 启动服务

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

浏览器打开 http://127.0.0.1:8000 。首次启动会自动建表并写入演示数据。

### 3.5 测试

```powershell
pytest -q
pytest -q -x -vv       # 遇到第一个失败就停，输出更详细
pytest -q --lf         # 只跑上次失败
pytest -q tests/test_shop.py::test_register_cart_checkout -vv
```

> 测试会在系统临时目录创建 `pyshop_test.db`，不会污染 `data/shop.db`。

### 3.6 VS Code 调试配置

在 `.vscode/launch.json` 增加：

```json
{
  "name": "PyShop-Uvicorn",
  "type": "debugpy",
  "request": "launch",
  "module": "uvicorn",
  "args": ["app.main:app", "--reload", "--host", "127.0.0.1", "--port", "8000"],
  "cwd": "${workspaceFolder}/examples/02-ecommerce-platform",
  "jinja": true,
  "justMyCode": false,
  "console": "integratedTerminal"
}
```

> `jinja: true` 让模板断点也能生效；`justMyCode: false` 便于跟进第三方库调用。

请求链路建议断点：

```text
浏览器请求
  → app/routers/*.py          （参数、鉴权、CSRF）
  → app/deps.py               （当前用户、require_admin、verify_csrf）
  → app/services/*.py         （购物车、下单事务、AI）
  → app/models.py / database  （SQL 与数据）
  → app/templates/*.html      （渲染）
```

### 3.7 调试认证与 CSRF

- 登录后浏览器 Cookie 中应有 `session`（HttpOnly）和 `csrf_token`。
- 所有 POST 表单必须带 `<input name="csrf_token" value="{{ csrf_token }}">`；漏掉会返回 400。
- 用 `Invoke-WebRequest` 调试时，先 GET 页面拿到 Cookie，再带同一 Cookie POST。
- 需要临时关闭 CSRF 排查时，不要改代码，优先用浏览器正常流程复现。

### 3.8 查看 SQLite 数据

不依赖额外工具，用 Python 直接查：

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/shop.db'); print(c.execute('select id,name,price,stock from products limit 5').fetchall())"
python -c "import sqlite3; c=sqlite3.connect('data/shop.db'); print(c.execute('select id,user_id,status,total from orders order by id desc limit 5').fetchall())"
```

或安装 DBeaver / 使用 VS Code 的 SQLite Viewer 打开 `data/shop.db`。

### 3.9 接口调试

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod 'http://127.0.0.1:8000/api/products?limit=3'
Invoke-RestMethod http://127.0.0.1:8000/api/products/1/pitch
```

表单类接口建议用浏览器或 Apifox/Postman，避免手工处理 Cookie 与 CSRF。

### 3.10 电商平台常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: app` | 不在项目根目录 | `cd examples/02-ecommerce-platform` |
| `Form data requires "python-multipart"` | 少装依赖 | `pip install python-multipart` |
| 启动报 `no such table` | 未触发初始化 | 通过 `uvicorn` 启动并访问一次，或调用 `init_db()` |
| 页面 400 CSRF | 表单缺 `csrf_token` 或未先 GET | 补隐藏字段，重新打开页面 |
| 401/403 | 未登录 / 非管理员 | 用对应账号登录，检查 `is_admin` |
| 下单提示库存不足 | 库存为 0 或并发扣减 | 后台补库存，检查 `services/order.py` |
| 订单 404 | 越权访问他人订单 | 正常防护，用本人账号访问 |
| 模板 `TemplateNotFound` | 模板名/路径错误 | 检查 `app/templates/` 文件名 |
| `database is locked` | 多进程同时写 SQLite | 只保留一个 uvicorn 实例 |
| 端口占用 | 8000 已被使用 | `--port 8001` 或结束占用进程 |

## 4. 调试方法论（通用）

1. **先离线、后联网**：采集先用 `--offline`，电商先跑 `pytest`，排除网络与环境。
2. **最小复现**：把请求缩到一条命令、一个测试用例。
3. **二分定位**：注释/跳过一半逻辑，逐步缩小范围。
4. **看日志与堆栈**：优先看最内层 `Caused by`，不要只看第一行。
5. **先写失败测试，再修代码**：修完用 `pytest -q --lf` 确认。
6. **改完必须回归**：`compileall` + 导入检查 + 全量测试。
