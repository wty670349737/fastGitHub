# 提交信息规范

## 语言要求

- 简短描述、正文、脚注**必须使用简体中文**
- 类型和范围标识符保持英文（属于代码标识符范畴）
- 技术术语首次出现使用"中文（English）"格式，如"断点续传（Resume Upload）"
- 广为人知的技术缩写可直接使用英文，如 API、SDK、HTTP、gRPC

## 格式

```
<类型>(<范围>): <简短描述>

[正文]

[可选脚注]
```

## 类型（Type）

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 Bug |
| docs | 文档变更 |
| style | 代码格式（不影响功能） |
| refactor | 重构（非新功能、非 Bug 修复） |
| perf | 性能优化 |
| test | 添加或修改测试 |
| chore | 构建过程或辅助工具变更 |
| ci | CI/CD 配置变更 |
| revert | 回滚提交 |


## 环境配置

- Git 可执行文件路径：`C:\Program Files\Git\bin\git.exe`
- 获取暂存变更命令：`& "C:\Program Files\Git\bin\git.exe" diff --cached`

## 规则

- 正文必须以- 开头
- 简短描述使用中文，不超过 50 个字符，不以句号结尾
- 正文每行不超过 72 个字符
- 正文说明"做了什么"和"为什么"，而不是"怎么做的"
- 破坏性变更在脚注中注明 `BREAKING CHANGE:`，说明文字使用中文
- 不得使用英文描述功能变更，即使是技术性内容也应翻译为中文表达
